## [Unreleased]

### Added
- **`--judge decision2`: Decision 2.0, open decision models run locally at a pinned revision** (US-008-001, #131). Loads any of the six Decision 2.0 sizes (vLLM Semantic Router, Apache-2.0) through the model's own runtime (`pip install 'kunko-judge-audit[decision2]'`, `DECISION2_MODEL`, default Kai-0.6B). Confidence is the probability of the chosen option; the model's `confidence` field, a normalized entropy 1 − H(p)/log K, is kept in `raw` as `entropy_confidence` and never audited. Yes/no and score questions are read as for Jev (score: the most probable level). The repositories changed after release and ship their runtime code, so a released model loads at a commit pinned in the adapter unless `DECISION2_REVISION` names another, and any other Hub id needs one. Provenance records the commit requested and loaded, the package's weight identity, calibration file and applied softmax temperatures, the device, library versions and every loader warning (transformers 5.17 warns of an "incorrect regex pattern" in the tokenizer). Before the first decision the adapter checks that the loaded tokenizer encodes probe texts exactly as the package's `tokenizer.json`, and that the model card's example gives the outputs recorded for that revision and kind of device (Kai-0.6B on CPU and MPS, where the runtime computes in FP32; CUDA, which uses BF16 autocast, and the other sizes are marked `unchecked`); a difference raises. Over-length input, which the runtime refuses instead of truncating, is recorded as no answer. Unit tests with a stubbed model; an opt-in smoke test on Kai-0.6B (`JUDGE_AUDIT_SMOKE_DECISION2=1`). No metric is published before the v0.6 pre-registration (#132).

## [0.5.1] — 2026-10-05

### Changed
- **A short README, the evidence of each version on its own page** (#128). The README leads with the question a team asks ("Can your AI judge decide alone?"), a 25-second demo, the v0.5 summary and an at-a-glance table, the quickstart and what a report looks like; the v0.5 study in detail is `docs/results/v0.5.md` and the v0.4 results (emails under attack, the Jev audits, the Arena, the consensus panel) are `docs/results/v0.4.md`. `scripts/verify_readme.py` checks the README and both pages as one text (508 figures), including every figure the demo GIF shows (`docs/assets/demo-figures.json`, against `docs/v05-results.json` and the two commands the demo shows, run as shown). The launch video is attached to the release.
- **The HTML report reads as a document** (#126; `render_html`): a cover with scope and key-figure cards (the safe automation rate at the primary target, accuracy, ECE, cost and latency), numbered sections, the data and ground-truth note as a callout before section 1, every metric and the interval notes in a closing section, and a print stylesheet so the browser's "Save as PDF" gives an A4 report. One type family and one size scale throughout; number tables compact and tabular. Markdown that used to leak into the page (backticks, `**†**`, `*lower bound*`) is converted after escaping, so no value from the data becomes markup. Same numbers, same sections; `docs/audit-jev-real.html` regenerated.
- **The public tree is for contributors** (#127). The sdist no longer ships the maintainer's editor and agent configuration (v0.5.0's did). `CONTRIBUTING.md` says what helps most (a reproducible metric bug, a judge adapter, a labelled dataset, an audit with its checkpoint), the evidence rules, the development commands and how review works; two issue templates (bug report, proposal for a judge, dataset or audit) and a pull-request template replace the planning templates. The maintainer's editor and agent configuration (`CLAUDE.md`, `.claude/`), the launch-video sources (`docs/launch/`; the videos stay attached to the v0.3.0 release), the positioning brief and the backlog script (`scripts/make_issues.py`) leave the tree and are git-ignored; no code, metric, report or test of the package changes.

### Fixed
- **Zero-error coverage no longer prints "confidence ≥ None"** (#126). When the most confident group of decisions already holds an error the covered prefix is empty; 34 published reports said "(0 decisions, confidence ≥ None)" and now say "(none: the most confident group of decisions already holds an error)". Regenerated from their checkpoints; `runs_report.py --moved`: 0 points moved, 0 headlines changed.
- **Install hints name the published package.** The messages for a missing optional dependency, the `llm` judge's docstring and `docs/judges.md` said `pip install 'judge-audit[charts]'` / `[anthropic]`; the package on PyPI is `kunko-judge-audit`, so they now say `pip install 'kunko-judge-audit[charts]'` / `[anthropic]`.

## [0.5.0] — 2026-10-04

### Added
- **Metrics for the v0.5 benchmark, fixed in code before its pre-registration** (`judge_audit.metrics.selective`; `docs/judges.md` § Discrimination, selective prediction at a target risk, and paired comparisons). Library functions only: no v0.4 report prints them and no published number moves (`runs_report.py --check` is clean).
  - `failure_auroc` (a tie counts one half; `None` when every answer is right or every one wrong) and `aurc`, the area under the risk–coverage curve, taken as its expectation over the orders of tied confidences, so neither depends on row order.
  - `coverage_at_risk`: the share of decisions a judge can automate at a target risk r, with the threshold chosen on a calibration split by fixed-sequence exact binomial tests (one-sided, level 1 − δ, starting at the first cut that holds `min_rows_to_certify(r, δ)` rows: 299 for 1 %, 149 for 2 %, 59 for 5 %) and checked on a test split no row of which chose it. The bound assumes independent calibration rows: `coverage_at_risk_crossfit` splits by distinct text, reduces each half to one unit per text (`aggregate_by_group`) and pools the test halves; its partition depends on the texts and the seed, not on row order. Zero-error coverage stays; coverage at a target risk degrades more gracefully under label noise and with n, but still needs noise well below r and several times `min_rows_to_certify(r)` rows per half.
  - `paired_difference_ci`: the clustered bootstrap of statistic(A) − statistic(B), both judges scored on each resample, instead of reading whether two intervals overlap; `mcnemar_exact` for accuracy on the discordant rows.
  - `bootstrap_defined`, `failure_auroc_ci`, `aurc_ci`: the same resamples as every other interval, with the resamples where a statistic is undefined counted rather than dropped silently.
  - **MCE** (US-003-002, #12, first criterion): `maximum_calibration_error` over the ECE's bins under either binning, `worst_calibration_bin` with that bin's row count, and `mce_ci`. Printing it next to the ECE in the reports is the second criterion, left for the v0.5 reports.
- **Human-labelled public datasets for the v0.5 benchmark** (US-005-001, #86, first part). `scripts/fetch_real_datasets.py` fetches each dataset from its official repository at a pinned commit, checks every upstream file against a recorded sha256, and writes deterministic labels files whose header declares tier GT-3, the caveats, the source, licence (with its URL) and citation; CI reruns it with `--check`. A run on such a file copies the header's `source` into the checkpoint's run metadata, and the sdist leaves the CC BY data out. BANKING77 (CC BY 4.0): `examples/banking77/labels-test.jsonl`, the 3,080-query test split (77 intents; 3,079 distinct texts when case and whitespace are ignored, the rule every distinctness and train-overlap claim here uses, with the one repeated pair named in the header; 7 also appear in train and are marked `_meta.text_in_train`), and `labels-pilot.jsonl`, 4 train queries per intent for the pilot, never scored. CLINC150 (CC BY 3.0): `examples/clinc150/labels-test-banking-credit.jsonl`, the `banking` and `credit_cards` domains (900 queries, 30 intents) plus the 1,000 out-of-scope test queries as `out_of_scope`, a draft subset until the pre-registration fixes it. Licences, attribution and the changes made are in `docs/runs/README.md` and each dataset's `README.md`.
- **A relabelling tool for label noise, not yet a measurement** (`scripts/relabel.py`). A random sample stratified by label in proportion to its share (500 rows per dataset, seed 2026, indices committed before anyone labels them in `examples/*/relabel-sample.json`); a blind annotation sheet per annotator, in an order of that annotator's own, whose ids are sheet positions (never the dataset row index, which in a label-sorted file gives the label away) and which holds no dataset label; and a score of two annotators' sheets: their agreement and Cohen's kappa, each one's agreement with the dataset, the rows both label differently from the dataset (likely label errors) with a Wilson 95 % interval on their share, and the rows they disagree on, to adjudicate. No sheet has been filled: the label noise of BANKING77 and CLINC150 is not measured yet.
- **`LLM_EXTRA_BODY` and a log-probability smoke test** (US-005-003 #88, US-005-004 #89, groundwork). The OpenAI-compatible path of the `llm` judge accepts a gateway's routing object (`provider` or `providerOptions`, by exact name; any other field is refused), merges it into every call and records it in provenance (`extra_body`). When it pins upstreams, the upstream the gateway reports is kept per decision only if it is one of them (`raw.upstream_provider`), and the decision fails otherwise. Without routing fields nothing about a run changes, and a checkpoint is not resumed with different ones. `scripts/logprob_smoke.py` asks one endpoint once whether it returns numeric token log-probabilities for a model (exit 0 yes, 1 no or ignored, 2 failed, 3 unreadable shape) and removes the key from everything it prints or writes.
- **`--judge logprob`: an open model's own probability of each option** (US-005-004, #89). For open-weight chat models run locally with MLX (`pip install 'kunko-judge-audit[mlx]'`, `LOGPROB_MODEL`): the prompt runs once into a cache, each option's tokens extend it and are trimmed back, and an option scores the sum of its tokens' log-probabilities plus the log-probability of ending there, normalised over the options; the share of probability the model put on the options is kept (`raw.option_mass`). Log-probabilities are computed in float32 whatever the model's dtype (a bfloat16 softmax turned 0.95 into 1.0), the prompt is always scored whole, as generation sees it (a label that merges with its last token is tokenised alone and named in `raw.labels_tokenised_alone`), and the prompt, decision rule and confidence differ from the `llm` judge's, so the two rows do not isolate the confidence method. Nothing is sampled; thinking is switched off in the chat template (`LOGPROB_CHAT_KWARGS` adds to that default). Provenance records the Hub commit loaded, the mlx and mlx-lm versions, the chat-template arguments applied and the cache mode. The cached scores equal an independent full forward pass, and a bfloat16 model its float64 reference, on a tiny random model (`tests/test_logprob_mlx.py`, run in CI on Linux CPU); `scripts/logprob_selfcheck.py` repeats the cache check on the real model and measures throughput before a run.
- **`--judge laya`: Laya, an open-weight judgment model run locally** (US-005-003, #88). A second judgment model beside Jev, reproducible by anyone at no cost (`pip install 'kunko-judge-audit[laya]'`). Confidence is the probability of the chosen option, never Laya's entropy-based `confidence` field; the provenance records the model, the checkpoint revision requested and loaded, the package version, the shipped and applied softmax temperatures and the token budgets (`LAYA_MAX_LEN`, `LAYA_HEAD_MAX_LEN`); `act_probability` is kept per decision. Laya 0.3.20 truncates a question that exceeds its token budgets (it raises only in extreme cases), so the adapter checks the budgets itself with Laya's tokenizer and raises, naming what would be cut; the check agrees with Laya's own sequence builder on 15,000 random cases. The checkpoint is downloaded at `LAYA_REVISION` by the adapter (Laya's loader takes no revision) and the commit loaded is recorded, as are the device actually used and which softmax temperatures Laya clamped (confidence it calls uncalibrated). Choice questions only. The docs carry Laya's own caveats: near chance zero-shot, `act_probability` without usable signal. Listed by the CLI and the MCP server's `list_judges`.
- **Self-consistency confidence for the `llm` judge** (US-005-004, #89, groundwork). `LLM_SAMPLES=k` asks each question k times at `LLM_TEMPERATURE` and reports the majority decision (ties to the decision drawn first; case-insensitive for answers outside the options) with its share of the k samples as confidence; a sample with no answer, or a null decision, counts in k and votes for nothing. `LLM_TEMPERATURE=default` sends no temperature, for models that refuse the parameter, and is recorded as "provider default". Such a run is its own row (`llm:<model>:sc<k>`), and `scripts/audit_resumable.py` refuses to resume a checkpoint with a different model, method, temperature, k or prompt. Every sample's reply, usage, served version and verbalized number is kept in the checkpoint (a decision whose samples were served by different versions lists them all), and `scripts/reparse_checkpoints.py` re-votes them offline. Several samples at temperature 0 are refused; a custom provider's `call()` that takes a `temperature` keyword always receives it, and one that does not refuses any non-default temperature. Without reasoning, the vote share estimates the answer's probability, which `logprob` reads directly where an API allows; the docs say so. With both variables unset nothing changes: one call at temperature 0, verbalized confidence, the same request and record.
- **Power analysis for the v0.5 study** (US-005-006, #91, first part). `scripts/v05_power.py` → `docs/v05-power.md/.json`, seeded, regenerated in CI (about 50 s), no API call; every figure in its prose is computed from its tables. (A) Exact: the rows one set of automated decisions needs for its exact bound to show an error rate at most 1 %, 2 % or 5 % with 0 to 10 errors (299, 149, 59 with none; at 1 %, each further error costs about 129–174 rows), and one fixed set's 80 % power at a lower true rate, an upper bound on what the procedure in A2 achieves. Its largest simulated violation rate, 4.8 %, is consistent with the 5 % allowed. (B) Paired AUROC, from DeLong's variance on one large sample per cell, against the exact gap between the two assumed methods (0.0500; 0.0494–0.0496 with ties): the smallest difference resolvable is about 0.029–0.061 on BANKING77's 3,079 texts (the gap is resolvable in 6 of 8 cells) and 0.036–0.078 on CLINC150's 1,900 (2 of 8). (C) Paired ECE, simulated with its Monte Carlo error: about 0.019–0.024 and 0.026–0.030. The pilot's estimates replace the stated assumptions before the plan fixes n.

- **The safe automation rate: every report opens with what the judge can decide alone** (US-003-004, #122; plan: `docs/automation-certificate-plan.md`). Per question and target error (1, 2, 5, 10 %), the confidence threshold to deploy, the share of the labelled decisions it automates, its errors and its 95 % upper error bound (fixed-sequence exact binomial walk, starting at the cut that bounds the error with 2 errors; `metrics.selective.certify_threshold`, `judge_audit.certificate`). Units are decisions: a text that recurs in the labelled set counts as often as it recurs, and a decision without a confidence is never automated and stays in the denominator. The guarantee holds for traffic drawn like the labelled decisions, judged by the same judge and prompt, with the labels taken as right. Also reported: an out-of-sample check (threshold chosen on half the decisions, split by distinct text, applied to the other half; seed 0 and the spread over seeds 0–9), a per-text line when texts repeat (each text once; not always the more cautious reading), the worst segment above the threshold (true label by default, `--segment-by meta.FIELD` or `none`) with the errors that sit in segments too small to rank, and the scope it is valid for (judge, model, revision, prompt, data, date) with a review date 90 days later. Where it appears: `audit-result.json` (`certificate`), the Markdown and HTML reports ("Can I automate this?", before zero-error coverage), the CLI line (`safe_automation@5%=41.0%`, or `none` when no threshold passes), the MCP `run_audit` result and the Action's PR comment. `--target` sets the headlined error before the run (default 5 %); a report regenerated from an archived checkpoint uses the default and says the target was not fixed in advance. `judge-audit check --min-safe-rate RISK:SHARE` (Action input `min-safe-rate`) exits 1 below a minimum, comparing the exact share, not the rounded one; a missed minimum is reported as "BELOW THE MINIMUM", not as drift, and recorded in the verdict file as `gate_failures`. Action outputs: `safe-automation-rate` (the primary target) and `safe-automation-rates` (every target). Names taken from the data or the command line are flattened to one line before they are printed in a report, and `--segment-by` accepts only `label`, `none` or `meta.` plus letters, digits and `_`. Statistical evidence on the labelled decisions, not a conformity assessment. The tie rule: the ideal cuts fall after answers n/10, 2n/10, …; a cut that lands inside a run of equal confidences moves to the run's nearer end (the lower end when both are equally near), and cuts that coincide merge. A tie is never split, bins can be unequal (a judge that says 1.0 on 125 of 200 rows gets one bin of 125), and the value does not depend on row order (1,000-shuffle test). ### Fixed
- **No expected decision leaves the denominator silently** (US-004-015, #74). `run_audit` used to score only the questions a judge answered, so a judge that skipped the questions it was unsure of scored higher on a smaller `n`. Now a labelled question left unanswered is a no-answer record (wrong, confidence unknown) that stays in `n`; a second answer to one question, or a label naming no question, stops the audit (exit 2); answers to questions not asked are counted and dropped. A dataset error (a label naming no question, a blank or null label) is found before the first call, in the live runner for the whole file and in the resumable driver before each row. A skipped question has no latency (left out of p50/p99, so silence does not look fast) and costs nothing extra when the row's answers came back at a known price; a row that returns nothing at all leaves its call unaccounted, so the run's total cost reads unknown even for a priced model. `audit-result.json`, the MCP `run_audit` result, the CLI line (`answered=…/…`) and the report carry `completeness {expected, answered, missing, unexpected}`. `scripts/audit_resumable.py` writes a skipped question into the checkpoint as a no-answer and stops on a doubled one, and `scripts/check_complete.py` (in CI) proves all 58 committed checkpoints answer every labelled question of every row they cover exactly once — so no published number moves.
- **The metrics refuse a non-finite confidence instead of imputing one.** `max(0.0, min(1.0, nan))` is 1.0, so a NaN in a checkpoint used to become a full-confidence answer.
