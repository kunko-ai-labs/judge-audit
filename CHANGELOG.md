## [0.4.0] — unreleased (dated when tagged)

### Added
- **NLL (log loss) next to Brier, never clipped** (US-004-017, #76; the issue's "ε clipping declared" criterion amended after review). `negative_log_likelihood()` (top-label) with the same clustered-bootstrap interval as Brier, in every run report, `audit-result.json`, the CLI line and an Arena column. The repository had left log loss out because it is infinite when a judge says 1.0 and is wrong, and clipping that 1.0 would impute a confidence the judge never gave. It still does not clip: a report prints the number when it is finite and otherwise **∞** with `nll_infinite`, the count of answers declared certain and wrong, with no interval. Under attack (n=200) every chat model in the Arena has an infinite NLL — Claude Sonnet 4.5 2 such answers, Gemini 3 Flash 5, Llama 3.3 70B 12, DeepSeek R1 16, llama3.2 18, gemma4 29 — while Jev (0.122), DeBERTa NLI and the fine-tuned runs have none. The published numbers only gain fields (`nll`, `nll_ci`, `nll_ci_method`, `nll_infinite`); none moves. It is not added to the Arena's rank-reversal sentence, which stays about ECE, equal-mass ECE and Brier. `docs/judges.md` § Three calibration numbers replaces "Why no log-loss" with the rule above.
- **Every README table figure, and the hero chart's caption, is checked against its JSON** (US-004-013, #67). `scripts/verify_readme.py` reads the Jev-audit, Arena and consensus tables, the figures in the Jev "What it shows" cells and the hero caption and alt text, and compares each figure, interval and † mark with the JSON regenerated from the checkpoints, at no coarser a rounding than the column prints; a missing or duplicated row, a one-digit edit, or a caption that calls an overlapping gap separated fails CI. Other README prose is not parsed. The hero chart draws each judge's 95 % interval, and the caption under it states the data are GT-1 synthetic (200 emails, 189 distinct texts), each judge ran once, and which gaps the intervals separate: Jev from the five judges at 0 % (exact upper bound 1.8 %) and DeBERTa NLI below it and from fine-tuned run 1 above it; not from Claude Sonnet 4.5 (0 %, interval up to 90.9 %) or fine-tuned runs 2 and 2+TS.
- **Release hygiene** (#62). `release.yml` now runs `build` → `smoke` → `github-release` → `publish`, each after the previous one passed. `smoke` installs the built wheel (plus its `mcp` extra) in a clean, pip-less virtual environment, checks `judge-audit --version` equals the tag, runs a simulated `judge-audit run` and `judge-audit-mcp --help`, then generates a CycloneDX 1.6 SBOM of that install (root component `kunko-judge-audit`; `cyclonedx-bom==7.4.0` installed with `--require-hashes` from `.github/sbom-requirements.txt`), and checks its root. Only then does `github-release` attest the wheel, sdist and SBOM with the same pinned Sigstore action and attach them to the GitHub release, and `publish` send them to PyPI: a failing smoke test leaves both untouched. Only jobs that install nothing hold `id-token: write`. Every checkout sets `persist-credentials: false`. `docs/RELEASING.md` documents what the SBOM covers and what it does not (the judges' hosted models are not Python dependencies; the Node bridge's npm packages are installed outside the Python environment).
- `scripts/protect_main.sh` adds the CodeQL `analyze` check to the required status checks and is idempotent (an existing `release-tags` ruleset is updated, not re-created). It deliberately does **not** require an approving review: this is a single-maintainer repository, an author cannot approve their own PR, and a required approval would force an admin bypass on every merge that also skips red CI. `CONTRIBUTING.md` § Review states what the independent review is instead — the `story-reviewer` and `release-qa` agents, whose verdicts the team lead posts on the PR as a comment before merge, plus the maintainer's own read — says it is not a second person's approval, and that an external reviewer is sought.

- **Brier score and equal-mass ECE next to the ECE** (US-004-012). `brier_score()` (top-label: mean of (confidence − correct)²) and `expected_calibration_error(..., binning="equal_mass")` are in `judge_audit.metrics.calibration`. The tie rule: the ideal cuts fall after answers n/10, 2n/10, …; a cut that lands inside a run of equal confidences moves to the run's nearer end (the lower end when both are equally near), and cuts that coincide merge. A tie is never split, bins can be unequal (a judge that says 1.0 on 125 of 200 rows gets one bin of 125), and the value does not depend on row order (1,000-shuffle test). With few distinct confidences the equal-mass ECE is sensitive to that rule, and `docs/judges.md` § Three calibration numbers says so: under attack a quantile rule that lets ties join the lower bin gives Sonnet 4.5 0.031 and Gemini 3 Flash 0.037, where this rule gives 0.044 each. Brier, which has no bins, is the robust check. Both numbers carry the same 95 % interval as the ECE: clustered bootstrap over distinct texts, 2,000 resamples, seed 0 (`brier_ci`, `ece_ci(..., binning="equal_mass")`). New fields `ece_equal_mass`, `brier` and their `*_ci` / `*_ci_method` appear in the audit JSON, the MCP `run_audit` result, the Markdown and HTML report header, the `judge-audit run` summary line and the per-run reports `scripts/runs_report.py` regenerates. They are `null` / `—` when there are no rows, never 0. Log-loss is absent on purpose: one wrong answer at a declared 1.0 makes it infinite, and clipping would impute a confidence.
- **Arena table: `ECE (equal-mass)` and `Brier` columns**, with intervals, both to four decimals so a near-perfect judge does not print a fake `0.000`. One generated sentence counts the reversals: the three numbers do not order the judges the same way on any of the four datasets; 28 judge pairs swap places, and none of those swaps is separated by the intervals of both numbers involved. No composite score is formed. The widest move is Llama 3.3 70B under attack (n=200): ECE 0.015 [0.005, 0.060], equal-mass ECE 0.133 [0.103, 0.174], Brier 0.0850 [0.0510, 0.1213]. The fixed 0.9–1.0 bin let the under-confidence of its 160 answers at 0.9 (98.8 % right) cancel the over-confidence of its 23 at 0.99–1.0 (47.8 % right; all 12 at 1.0 wrong). Under attack, Sonnet 4.5 and Gemini 3 Flash beat Jev on ECE (0.016 and 0.015 vs 0.039) and on Brier (0.0307 and 0.0301 vs 0.0355). With this tie rule their equal-mass ECE is 0.044 each against 0.037; every one of those intervals overlaps. README quotes it with the tie-rule caveat.
- **◊: a point estimate outside its own interval is marked.** `ci_fields(name, ci, point)` adds `<name>_ci_point_outside: true` when the point lies outside its percentile interval, and every table built on `interval_of` prints `◊` with a legend line. - **`clopper_pearson(successes, n, alpha=0.05)`** (`judge_audit.metrics.calibration`): the exact binomial interval, from the Beta quantiles that invert the binomial test, computed in pure Python with `math.lgamma` (a continued fraction for the regularised incomplete beta) and a bisection — no SciPy, identical on every supported Python. 0/10 → `[0.0, 0.3085]`, 10/10 → `[0.6915, 1.0]`, 8/10 → `[0.4439, 0.9748]`. `proportion_ci` uses it where the clustered bootstrap degenerates; `Interval` carries the method that produced it and `ci_fields` publishes both in the JSON.

### Changed
- **Latency percentiles use a named standard method; every report that prints a p99 prints the slowest call next to it** (US-004-017, #76): p50 and p99 are interpolated between order statistics (Hyndman–Fan type 7, numpy's default), the rule the bootstrap already used for its interval cut, instead of two copies of the same non-standard shortcut (`s[int(p·n)]`) in the runner and the adversarial analysis. 102 published latency values in 58 files move: 46 p50 (9 by more than 10 ms, at most 123 ms: jury round 2 bare-label gemma4 17.144 → 17.021 s) and 56 p99. ### Fixed
- **No expected decision leaves the denominator silently** (US-004-015, #74). `run_audit` used to score only the questions a judge answered, so a judge that skipped the questions it was unsure of scored higher on a smaller `n`. Now a labelled question left unanswered is a no-answer record (wrong, confidence unknown) that stays in `n`; a second answer to one question, or a label naming no question, stops the audit (exit 2); answers to questions not asked are counted and dropped. A dataset error (a label naming no question, a blank or null label) is found before the first call, in the live runner for the whole file and in the resumable driver before each row. A skipped question has no latency (left out of p50/p99, so silence does not look fast) and costs nothing extra when the row's answers came back at a known price; a row that returns nothing at all leaves its call unaccounted, so the run's total cost reads unknown even for a priced model. `audit-result.json`, the MCP `run_audit` result, the CLI line (`answered=…/…`) and the report carry `completeness {expected, answered, missing, unexpected}`. `scripts/audit_resumable.py` writes a skipped question into the checkpoint as a no-answer and stops on a doubled one, and `scripts/check_complete.py` (in CI) proves all 58 committed checkpoints answer every labelled question of every row they cover exactly once — so no published number moves.
- **The metrics refuse a non-finite confidence instead of imputing one.** `max(0.0, min(1.0, nan))` is 1.0, so a NaN in a checkpoint used to become a full-confidence answer. Every calibration metric raises a `ValueError` naming the row for NaN or ±infinity, and `runner.clamp_confidence()` — used by the runner and by every script that reads a checkpoint (`audit_resumable`, `arena_report`, `verify_published`, `heldout_report`, `audit_router`) — returns `None` for such a value (since #70, below), so it is counted as unknown and never reaches a metric. The chat-model adapter (`judges/llm.py`) still clamped a model-written `"NaN"` to 1.0 at parse time; that is fixed by the next entry (#70).
- **A simulated result says so on the line people copy.** `judge-audit run`, `judge-audit check` and its drift verdict printed `judge=simulated …`, `OK: no drift …` or `DRIFT DETECTED:` without the SIMULATED tag that the report, the JSON and the PR comment carry, so a pasted summary line from a simulated run read like a real audit; release QA for #63 flagged it against the contract in `.claude/agents/release-qa.md`. Each of those lines now starts with `SIMULATED — not a real vendor audit · ` when the judge is simulated, and only then; tests pin all three.
- **Unknown confidence stays unknown** (US-004-014, #70). The chat-model adapter used to impute a confidence it was never given: an unparseable reply, a missing or non-numeric `confidence` became 0.0, and `"NaN"` became 1.0 through the clamp. A `Judgment` now carries `confidence: float | None` and a `parse_status` (`parsed`, `no_answer`, `no_confidence`). NaN, ±infinity, a missing value, a non-number (including JSON `true`/`false`) and a value outside [0, 1] all become `None`: out-of-range values are rejected, never clamped. A blank or missing decision is `no_answer`, and its confidence is unknown even when the model wrote a number: that number belongs to no decision. A decision outside the options is an answer — a wrong one — and keeps the confidence the judge declared. Accuracy is still computed on every row, a no-answer counting as wrong; ECE, equal-mass ECE, Brier, zero-error coverage and the accuracy–coverage curve use only the rows with a known confidence, with the confidence, correctness and clustering group filtered by the same indices. With no known confidence the calibration numbers are `null` / `—`, never 0. - Consensus and jury reports index panel votes by row id, so a resumed run whose redone rows were appended out of order no longer misaligns judges.
