# v0.5 pilot on the BANKING77 train sample — protocol

**Issue:** [#91](https://github.com/kunko-ai-labs/judge-audit/issues/91) · **Status:** committed before the first model call of the pilot (2026-09-27 08:55Z). Its amendments, with times from the git log and the checkpoint headers (UTC): the §3–§5 estimation rules, after an independent review (09:16:12Z), before any pilot run (Laya's header 09:16:38Z; a 20-row `logprob_selfcheck.py` attempt, which computes no accuracy, had been started); the hosted approval and its $2 ceiling (09:47:22Z) before the hosted calls it governs (gemini-3.6-flash verbalized 09:47:44Z, Jev 09:49:30Z), and Gemini's ceiling raised to $5 (09:54:25Z) before its self-consistency run; the §4.1 self-check cut to 5 rows (10:07:39Z) **after** the Laya, Jev and Gemini verbalized runs had started and before the log-probability run it gates (10:47:02Z). Nothing in this pilot is a result about any judge.

## 1. Why

[`docs/v05-power.md`](v05-power.md) sizes the v0.5 study on assumed shapes: the accuracy of the judges, how strongly two confidence methods agree on which rows are hard (ρ), and how tied the confidences are. The pilot measures those three things on data the study never scores, so that `scripts/v05_power.py` runs on estimates rather than guesses before `docs/v05-plan.md` fixes n, the certification targets and the smallest detectable differences. It also measures throughput, parse failures and the token log-probability judge's `option_mass`, which the plan needs for time and cost.

The pilot does **not** test H1 or H2. With 308 rows it could not, and a comparison on it would contaminate the pre-registration. Its per-judge accuracies are planning inputs, published only as such, next to this caveat.

## 2. Data

- `examples/banking77/labels-pilot.jsonl`, sha256 `488ee2258027c6f4901600f6adfce55d33e620d63ff9fa69178fe04cd0a5f7ed`: 308 queries from the BANKING77 **train** split, 4 per intent, one `intent` question with the 77 label names as options. The study scores the test split only.
- Caveats (from the file header): public since 2020, probably in pretraining data; about 14 % of train queries flagged as possibly mislabelled by automated detection (Ying & Thomas 2022); label names without definitions, some misleading. Label noise is not measured here.

## 4. Order, checks and stopping rules

1. `LOGPROB_MODEL=mlx-community/Qwen3-8B-4bit LOGPROB_REVISION=545dc4251c05440727734bcd94334791f6ab0192 python scripts/logprob_selfcheck.py examples/banking77/labels-pilot.jsonl --rows 5` (amended from 20: the check's full-forward reference path, one uncached pass per option, grew to 12 GB resident and swapped for over an hour without finishing, so it was stopped before it printed anything and rerun on 5 rows, 385 option probabilities; the judge itself uses only the cached path). **Stop** the `logprob` run if it exits 1 (a probability off by more than 1e-3, or a decision that changes); the check's output is reported either way.
2. `laya`, then `logprob-qwen3-8b`, then (server up) `llm-qwen3-8b`, then `llm-qwen3-8b-sc5`, each with `scripts/audit_resumable.py … --checkpoint docs/runs/v05-pilot/<slug>.ckpt.jsonl`, in the background, polling the row count. The drivers' own Markdown and JSON reports go to a scratch directory and are not committed: they would read as scores.
3. **Stop** an `llm` run, and amend this protocol in a commit before changing anything, if more than 5 % of its first 40 rows have no parsed answer; for the self-consistency run the count is of samples (of the first 200), since a failed sample counts in k, votes for nothing and silently lowers the confidence. Failed samples are counted and reported for the whole run. No prompt, setting or model changes mid-run.
4. A run that dies is resumed by the driver (it refuses to resume under a different configuration). A row that keeps failing is left missing and counted.

## 5. What is estimated, and how (fixed now, before any row is seen)

A committed, deterministic script (`scripts/v05_pilot.py`, no model call, seeded) reads the four checkpoints and writes `docs/v05-pilot-estimates.md` and `.json`; CI regenerates them. Each estimate is printed with its n and, where stated, a 95 % interval.

Rows whose decision carries no confidence (`no_confidence`) or no answer are counted per run and left out of the tie shares, the Spearman correlations and the AUROC; they count as wrong in accuracy.

| Estimate | Definition | Feeds `scripts/v05_power.py` |
|---|---|---|
| Accuracy per run | decision equal to the label, case ignored; a row with no parsed answer counts as wrong; Wilson 95 % interval. Measured on train, not on the test split the study scores | `ACCURACIES` ← the distinct accuracies of the three Qwen3 read-outs, rounded to 0.01, **plus the Wilson upper bound of the highest** (more accuracy means fewer errors and a larger MDE: the conservative cell) |
| Decision agreement | per pair of Qwen3 read-outs: share of rows with the same decision, and share with the same correctness | not fed back; it measures how far the power model's assumption of one shared set of decisions (part B) is from this design |
| Tie shares | per run, the share of rows at each distinct confidence value (rounded to 1e-6), lowest to highest | part B's tied cells become per method: `TIE_SHARES_A` ← the verbalized run's shares, `TIE_SHARES_B` ← the self-consistency run's shares (the primary H1 pair); the script's "6 levels" wording becomes the number of levels of each |
| Verbalized distribution | the verbalized run's confidences rounded to 0.05; a level holding under 1 % of rows is pooled into the nearest kept level (a tie goes to the lower level, the less flattering one); weights rounded to 0.001 with the rounding remainder added to the largest weight, so they sum to 1 | `CONF_VALUES`, `CONF_WEIGHTS` (part C) |
| Rank agreement → ρ | for each pair of the three Qwen3 read-outs, on the rows **both** got right: the Spearman correlation (average ranks) of the two confidences. ρ is the latent correlation that reproduces it: one fixed sample of 100,000 standard normal pairs (seed 2026, common to every step), the second coordinate mixed as ρ·z₁ + √(1−ρ²)·z₂, each coordinate cut into levels with that method's tie shares **measured on the same both-correct rows** (the script's `levels`; a continuous method is not cut), Spearman computed the same way; bisection on ρ ∈ [0, 0.999] for 40 steps (monotone because the sample is fixed); an observed correlation at or below the ρ = 0 value maps to 0. Cutting the correct rows by their own shares makes the mapping independent of AUROC and accuracy. Interval: 2,000 bootstrap resamples (seed 2026) of the both-correct rows, the 2.5 % and 97.5 % percentiles of the Spearman correlation, each mapped the same way with the shares held at their full-sample values. The rows both got wrong are reported, not used | `RHOS` (part B only) ← the point estimates for the two H1 pairs (verbalized–self-consistency, verbalized–log-probability), rounded to 0.05, plus the lower interval bound of the smaller one (the conservative cell) |
| AUROC per run | AUROC of confidence for correctness, ties counted as half, with a DeLong 95 % interval | `AUROC_A` ← the **latent** AUROC that reproduces the verbalized run's observed AUROC: the μ with `population_auroc(μ, accuracy, TIE_SHARES_A)` equal to it (bisection), then Φ(μ/√2), rounded to 0.05 and capped at 0.90, so ties are not counted twice; `AUROC_B` = `AUROC_A` + 0.05 (the design gap is unchanged) |
| Outcome correlation between different judges | tetrachoric correlation of correctness between Laya and each Qwen3 read-out | **not fed back.** Part C's copula, which links the outcomes of two *different* judges (H2), gets its own constant `RHOS_C`, kept at the current design values 0.3 and 0.7: the within-model ρ above is a different quantity and, being likely high, would make the H2 ECE MDE optimistic; Laya near chance zero-shot is not a stand-in for Jev |
| Also reported, not fed back | overconfidence (mean confidence − accuracy) per run; no-answer, no-confidence and failed-sample counts; `option_mass` quartiles of the log-probability run; Laya's clamped softmax temperatures; rows per minute and tokens per call per run | — |

`GAP_A`, `GAP_B` (the ECE design gap), `RHOS_C`, `AUTOMATABLE`, `REST_ERROR` and the grid of n stay as they are: they are design choices, not quantities the pilot measures. Two known limits of the power model stay and are printed with its tables: part B scores both methods on one shared set of decisions (here they differ; the decision agreement above says by how much), and part C draws each judge's confidence independently. The plan names the power-analysis cell the pilot matches and states its MDE.

## 5b. Amendment (2026-09-29): self-consistency at k = 10, before its first call

The k = 5 run left 82.1 % of rows unanimous, so its confidence barely ranks the rows (the planning finding in [v05-power.md](v05-power.md) § B). The maintainer decided (plan decision D1) to measure k = 10 on the same rows before fixing k for the study. Committed before this run's first call; nothing in §3–§5 changes for the runs already made.

- **Run** `llm-qwen3-8b-sc10`: the same checkpoint, server, prompt and settings as `llm-qwen3-8b-sc5` (§3), with `LLM_SAMPLES=10`, `LLM_TEMPERATURE=1`; 308 rows; checkpoint `docs/runs/v05-pilot/llm-qwen3-8b-sc10.ckpt.jsonl`.
- **Stop rule** as §4.3, scaled: more than 5 % failed samples among the first 400 (the first 40 rows) stops it.
- **Estimated as for the other runs** (§5 rules; confidences compared exactly, the sensitivity rule, since k = 10 votes take at most 10 values): accuracy, tie shares, AUROC, decision agreement with the verbalized run, Spearman and latent ρ against the verbalized run on the rows both got right.
- **Decision rule, fixed now:** the study uses **k = 10 for Qwen3** if this run's share of rows at its top confidence level is below the k = 5 run's 82.1 %; otherwise it keeps k = 5. Hosted models keep k = 5 (cost). The adopted run's tie shares replace `TIE_SHARES_B`, and its latent ρ against verbalized joins `RHOS`, in one reviewed commit that regenerates [v05-power.md](v05-power.md); the other run's numbers are reported beside them.

## 5c. Amendment (2026-09-30): a cost probe for Gemini, before its first call

The maintainer's billing console showed 2.7 EUR for gemini-3.6-flash on 2026-09-29 against $0.59 recorded. One cause is known: the endpoint bills reasoning tokens it reports only in `usage.total_tokens`, which the judge did not count until #117; whether it is the only one is what the probe helps tell. To size the study's cost ceiling (plan D6/D7), the fixed judge runs once more on the first 20 pilot rows (`docs/runs/v05-pilot/cost-probe-rows.json`), verbalized (T = 0) and self-consistency (k = 5, T = 1), same model, endpoint and prompt as §3: checkpoints `llm-gemini-3.6-flash-probe` and `llm-gemini-3.6-flash-sc5-probe`. Estimated: the mean billed output tokens per call (itemised + hidden) for each, and the cost per call at list price. Nothing else is estimated from these rows; they feed no constant. Ceiling for the probe: $1.

## 6. What happens next

The constants are changed in one reviewed commit that cites `docs/v05-pilot-estimates.json`, `docs/v05-power.md` is regenerated, and `docs/v05-plan.md` is drafted from it and reviewed before the study's first call. Estimates are published whether or not they are convenient: if ρ is low or accuracy high, the MDEs grow, and the plan says so.
