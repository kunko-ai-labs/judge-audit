# Robustness check: one row per distinct text

> Generated by `scripts/distinct_report.py` from the committed checkpoints — no API call. Regenerated in CI.

The generators repeat some texts (#54). The published intervals already resample distinct texts, but a repeated text still counts twice in the point estimate. Here every Arena statistic is recomputed on the **first row of each distinct text** (file order), so a reader can see which numbers lean on the repeats. Same judges, same rules as the Arena table (full-dataset runs only); same 95 % intervals over distinct texts (exact binomial where the bootstrap cannot move, marked †).

**The README headline holds on distinct texts.** Under attack, on 189 distinct texts, Gemini 3 Flash's zero-error coverage is 0.0% (95 % upper bound 1.9 %) and Jev's is 72.0% [66.1, 93.7]; the intervals do not overlap.

**Read the router with care.** Deduplicating the router keeps 61 of 120 rows, and the repeats sit in its easy and hard segments: it goes from 40 easy / 40 hard / 40 injected to 14 easy / 14 hard / 33 injected. So the distinct-text router is mostly the injected segment, and its accuracy moves because the *question mix* changes, not only because repeats are gone. Compare the router rows with that in mind; the email datasets keep their mix.

## Caveats

- Every dataset is GT-1 synthetic: ground truth by construction, small n.
- Which row of a repeated text is kept is a rule (the first in file order), not a sample; a judge that answered the repeats differently is scored on one of its answers only.
- This does not replace a dataset without repeats; the pre-registered replication on v2 data is the stronger test.
