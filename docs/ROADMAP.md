# Roadmap

What shipped, what is next, and why. Issues on GitHub are the live backlog; this file is the narrative.

| Version | What | Why |
|---|---|---|
| v0.1 (done) | Harness: pluggable `Judge`, shadow-mode runner, ECE + reliability bins + accuracy-coverage + zero-error coverage, cost and p50/p99, Markdown/HTML reports, `check` CI gate, simulated judge | The questions a buyer asks before automating, answerable without trusting the vendor |
| v0.2 (done) | **Independent audits of a vendor judge** (Jev via the AI Gateway evaluate API): clean emails, adversarial emails, task routing + the option-description ablation; raw checkpoints committed; provenance in every report; `verify_published.py` in CI; **`llm` adapter** (Claude via SDK, any OpenAI-compatible endpoint) and **Jev-compatible endpoints** (OpenJev) through `JEV_ENDPOINT`; Apache-2.0, tests, CI | A number without its evidence is an opinion. The repo goes public with every claim reproducible, and with the adapters people need to audit what they actually run |
| v0.3 (done) | **MCP server** (`judge-audit-mcp`: `run_audit`, `check_drift`, `list_judges`) so agents and IDEs audit a judge in place; **GitHub Action** (`mode: run \| check`, sticky PR comment with the audit table, self-demo workflow) for the Marketplace; launch video | Distribution: the audit has to live where the judge is used — the agent session and the pull request |
| v0.3.x | **Side-by-side** (#21): Jev vs local open models (Ollama) vs Gemini / Claude on the four datasets, checkpoints committed, `docs/arena-2026-09.md` | A side-by-side on the same data and harness is what a buyer asks for |
| v0.3.x | **Consensus audit** (#39): the Arena judges as a jury — is vote share a confidence score? — plus a pre-registered deliberation round (Shao 2026, Huang et al. 2026) | An agent jury often treats agreement as evidence; a calibration audit is where that assumption gets tested |
| v0.4 (first stories) | **Fine-tuned classifier baseline on a pre-registered held-out split** (#53); **intervals on every published number**, exact where the bootstrap degenerates (#59); release hardening: escaped PR comment, no home paths in committed files (#58) | "Isn't a judgment model just a classifier?" deserved a measured answer, and a repository about calibration cannot publish a zero-width interval |
| v0.4.0 (released 2026-09-26) | **The instrument, corrected and auditable**: order-independent zero-error coverage; a drift gate that refuses incompatible baselines; an Action that treats its inputs as data; unknown confidence never imputed; no decision leaves the denominator silently; Brier, equal-mass ECE and NLL (never clipped) next to the ECE; type-7 latency percentiles with the slowest call; the served model version recorded; every README table figure checked in CI; the headline repeated three times under pre-registration and checked on distinct texts (#85) | The 22-Sep audit (#81): the claims had run ahead of the instrument, and a buyer needs numbers that survive a hostile recomputation |
| v0.5.0 (released 2026-10-04) | **A pre-registered study on real data** (#94, #91): BANKING77 test and a CLINC150 subset, human-labelled, plus the v2 stress sets (36 runs in all), 8 confirmatory tests frozen before the first call, every result published ([docs/v05-results.md](v05-results.md)); confidence measured three ways — verbalized, token log-probability (`--judge logprob`, MLX), self-consistency — for Qwen3-8B, and two of them for gemini-3.6-flash (#89, first part); v2 stress sets without duplicate texts (#87); repeats for Jev and Qwen3-8B verbalized (#90, first part); a second prompt template, exploratory (#92, first part); **the safe automation rate** in every report, the CLI, the MCP server, the PR comment and the Action, with a `--min-safe-rate` gate (#122). Explained for readers in [docs/v05/](v05/README.md) | v0.4's evidence was synthetic, small and limited to two tasks; a buyer's first question is how much a judge can decide alone, and at what error |
| v0.5.1 (released 2026-10-05) | The HTML report as a printable document (cover, key figures, numbered sections) and the "confidence ≥ None" fix (#126); a public tree for contributors (#127); a short README with results per version and a demo whose every figure is checked (#128) | What a reader sees first should be as honest as the numbers behind it |
| v0.6.0rc1 (pre-release, 2026-10-07) | A pre-release of what is on `main`: the open decision models as judges, MASSIVE in three languages, the first cut as data, the judgments digest in every result, the error rate at high stated confidence (#134). No study result | A signed build to install and verify before 0.6.0 |
| v0.6 | What v0.5 did not finish, carried over: a truly unseen held-out slice with two annotators (#106, #86); current OpenAI and Claude models and a guardrail classifier in the roster (#88); every confidence method for every model that exposes it (#89); repeats for every judge (#90); prompt sensitivity for every judge (#92); the literature and the other public Jev audits compared (#93); MCE in the per-run report (#12). Then the **public leaderboard** (#14, #15) with a submission spec | The v0.5 caveats, closed one by one, before a leaderboard ranks anyone |
| later | Score questions (graded answers, not only choices); conformal-prediction coverage guarantees (research) | Research directions |

Out of scope: building a judge. judge-audit checks judges; it does not compete with them.
